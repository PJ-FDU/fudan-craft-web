# 3D 模型与材质

实际参数以源码为准；本说明对应当前 Three.js / WebGL 2 战场。

## 模型

- `src/game/model-parts.ts`：共用倒角、曲面、圆环等几何体。`bevel` 使用真实圆角并保留上窄下宽的轮廓；法线随收窄变换，保持高光连续。圆柱为 20 段，头盔曲面为 20 × 12 段。螺栓仍采用 8 段，植被没有增加细分。
- `src/game/mobile-models.ts`：装甲连接件、头盔导轨、弹匣袋与装具、车体检修盖、百叶、轮毂螺栓、轮胎胎块、履带块、分段侧裙、炮塔挂架、炮管加强环。战机采用翼尖收薄的后掠翼，增加进气叶片和喷口瓣片；机甲增加液压弯管。细节绑定已有骨骼，沿用车轮、炮塔、抓钳与翼面的动画。
- `src/game/models-3d.ts`：建筑侧窗、结构缝、卷帘门、扶梯、管道法兰、阀轮、回流弯管、设备支架、护栏、屋顶风机与背墙百叶。研究中心使用平滑玻璃穹顶。

九类移动单位仍各自合并为实体、阵营色、灯光三个 SkinnedMesh；同种单位共用几何体，各自拥有独立骨架。静态建筑为三个 Mesh；带独立炮塔或天线的建筑为五个 Mesh。这里是模型网格数，不含选中地面标记；阴影等渲染阶段还会产生额外绘制。

当前单个模型为 2,076–12,840 三角形；坦克和火炮最高。没有为每块履带或螺栓建立单独 Mesh，也没有引入逐帧反射探针。实际帧率仍取决于屏幕分辨率、可见部队数量与 GPU。[当前模型预览](refined-assets-preview.png)。

## 材质与光照

`src/game/model-surface.ts` 定义每类表面的粗糙度、金属度和凹凸强度：

| 表面 | 粗糙度 | 金属度 |
| --- | ---: | ---: |
| 喷漆装甲 | 0.48 | 0.32 |
| 屋面金属 | 0.30 | 0.78 |
| 液压活塞 | 0.24 | 0.85 |
| 橡胶履带 | 0.86 | 0.02 |
| 织物 | 0.94 | 0 |
| 玻璃与光学器件 | 0.16 | 0.42 |

这些值通过 `surfaceFinish` 顶点属性传入同一材质。粗糙度叠加轻微纹理变化。`src/game/surface-normals.ts` 在首次使用时生成共用的 1024 × 512 线性法线图集，包含织物编织、装甲接缝、橡胶纹路、百叶和粗糙石材；法线强度按表面参数缩放，玻璃保持平滑。不再把颜色图集中的绘制高光、阴影当成凹凸。这是程序化材质细节，未使用扫描资产或高模烘焙法线；玻璃仍是有反射的不透明表面。

`src/game/model-weathering.ts` 为四族单位与建筑共用的 56 类表面定义污垢、腐蚀、擦伤和撞击强度。金属使用局部锈斑、油污、掉漆和零星弹痕；铜与合金使用氧化色；陶瓷与复合板露出较暗底层，甲壳、织物与橡胶使用擦伤和积灰。阵营色板使用同一做旧材质。裸露皮肤在 `humanoid-models.ts` 中显式降低磨损。

- **[WEAR-REST]** `Parts` 保留原始部件 UV、尺寸、静止高度与固定种子，纹理在模型移动、旋转和蒙皮时保持在原表面上。噪声基础尺度为 10 个模型坐标单位；近地积灰在静止高度 2–25 之间衰减，独立活动构件计入安装高度。
- **[WEAR-PBR]** 磨损同时影响颜色、粗糙度、金属度和表面梯度法线；属于预设使用痕迹，不随当前生命值增加。树木、自然表面、发光件和建造预览不应用这层做旧。
- **[WEAR-BATCH]** 实体与阵营色几何携带相同的做旧属性，继续沿用 solid / team / lamp 合批；不新增纹理、独立弹孔 Mesh 或逐帧坐标写入。
- **[WEAR-VERIFY]** `tests/model-weathering.test.ts` 检查完整阵容的有限顶点属性、非金属不生锈、移动单位最多三个材质网格、动画前后坐标不变，以及高处油井设备不误用地面积灰。构建与 181 项测试通过。浏览器逐项渲染了 77 个种族／对象组合及装配站收拢形态，并验证真实战场的光照与迷雾，未记录到脚本或着色器错误。[四族实机效果](faction-materials/weathering-preview.jpg) · [实战视角](faction-materials/weathering-battle.jpg)。

`src/game/battle-lighting.ts` 使用程序化天空生成 PMREM，初始化时烘焙一次。ACES 曝光为 1.12，场景环境强度为 0.65。天空提供粗糙反射与间接环境光，实时方向光负责明暗和投影。

`src/game/battle-scene.ts` 在初始化时按视口宽度选择阴影贴图：小于 700 为 1024，小于 1200 为 2048，否则为 4096，同时受设备最大纹理尺寸限制。阴影仍最多更新 30 次/秒，偏移随镜头进行纹素对齐。

战争迷雾的 `onBeforeCompile` 与模型 PBR 钩子组合，程序缓存键同时包含两者。添加材质效果时必须保留这一组合，避免丢失表面参数或视野遮蔽。

## 动态间接光

`src/game/battle-gi.ts` 实现 WebGL 2 的屏幕空间漫反射反弹，属于 SSDO 类近似。它会读取当前可见表面的出射光，计算一次颜色反弹；接触遮蔽是另外计算的效果，不能单独视为 GI。

1. 主场景渲染至全分辨率 RGBA16F 颜色与深度目标，MSAA 最高 4 倍。
2. 从深度重建观察空间位置和几何法线，在 54 世界单位半径内采样可见表面，结合收光角、出光角和距离估算反弹光。中点深度检验抑制跨遮挡物漏光。
3. 低分辨率输出 RGB 间接光和 A 接触遮蔽；使用固定像素种子的交错旋转，随后执行 5 × 5 深度／法线双边降噪和全分辨率双边上采样。
4. 在线性 HDR 空间合成，最终只做一次 ACES 与 sRGB 输出。没有历史帧积累，也没有逐帧反馈多次反弹。

**[GI-DEPTH]** 重建位置与法线前必须对齐全分辨率深度纹素中心。半分辨率采样会落在纹素边界，直接差分可能重复采到同一行，造成明显条带。深度差分还会选择较连续的一侧，避免把物体轮廓当成斜面。

**[GI-FOG]** 反弹光的源表面和接收表面都必须经过当前战争迷雾纹理检查；最终合成再次遮蔽接收面。没有历史光照缓存，视野变化立即生效。

**[GI-LIMIT]** 该方法只知道当前画面最前层的颜色与深度；画面外、背面和被遮住的表面不能参与反弹，窗口边缘可能丢失贡献。没有独立 albedo G-buffer，接收表面反射率用有界颜色近似，因此不是物理精确的全局光照。微表面法线用于主光照，GI 只重建几何法线。透明、无深度写入的特效不能提供准确的 GI 表面。

原生 [Lumen](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine) 依赖 UE5 的屏幕追踪、场景表面缓存，以及软件／硬件光线追踪。本项目没有接入 Lumen、Nanite、距离场追踪或多次反弹；天空 PMREM 继续补充屏幕外的环境光。

## 档位与预算

战局菜单 → **间接光照**，选择后即时生效并保存在当前浏览器：

| 档位 | 间接光分辨率（相对实际绘制尺寸） | 每像素采样 | 默认 |
| --- | --- | --- | --- |
| 基础 | 关闭后处理 | 0 | 初始化视口宽度 < 700 |
| 均衡 | 宽高各 35% | 16 | 其他视口 |
| 精细 | 宽高各 50% | 32 | 手动选择 |

已有设置优先于默认值。缺少 `EXT_color_buffer_float` 的设备强制使用基础档；菜单控件会禁用并说明原因。基础档恢复直接渲染并释放大尺寸后处理目标。GI 增加三次全屏绘制，无需额外重画场景几何的法线 pass；DPR 仍受现有上限 2 约束。

2026-11-19，在 Chrome / ANGLE Metal / Apple M3 Pro、1440 × 872、DPR 1 的初始基地场景（10 个视野单位）测量。使用 `EXT_disjoint_timer_query_webgl2`，每档 24 次有效 GPU 查询，采样帧包含阴影更新：

| 档位 | GPU 中位耗时 | GPU P95 |
| --- | ---: | ---: |
| 基础 | 2.94 ms | 3.23 ms |
| 均衡 | 4.01 ms | 6.05 ms |
| 精细 | 5.92 ms | 7.86 ms |

这些数据只描述该场景的 GPU 绘制，不等于完整游戏 FPS，也不代表大规模部队、手机或其他 GPU 的性能。切换 390 × 844、1280 × 720、1440 × 872 并反复切换档位后，恢复精细档的纹理计数保持 19，没有随操作增长。

## 验证与边界

- TypeScript 与生产构建通过；71 项现有测试通过，覆盖骨骼独立性、移动与炮塔/抓钳动画、建筑占地及战斗规则。
- 浏览器实际渲染全部 18 类模型，几何属性均为有限数值，WebGL 错误码均为 0；[模型预览](refined-assets-preview.png)使用实际模型和同一套光照，[战场截图](battlefield-gi-preview.png)来自运行中的游戏。
- 用灰色地面／墙面与红色、蓝色自发光体检查反弹，固定相机、曝光和环境光。精细档间接光缓冲的红色通道总量从约 1618.67 降至 145.33，蓝色从约 153.62 升至 1626.96；AO 总量保持不变，确认颜色变化来自反弹光而非遮蔽。迷雾全部遮蔽后 RGB 与 AO 总量均为 0。[开关与颜色对照图](gi-comparison.png)额外将接触遮蔽强度设为零，单独显示反弹光。
- 实际 UI 检查战役部署、部队选择、缩放、三档切换与设置保存；390px 视口的菜单无横向溢出。生产构建仍有 Three.js 分块超过 500 kB 的体积提示。

## 选中光圈与生命值

[近距离效果](selection-health-preview.png)。

- **[SELECTION-DEPTH]** 选中光圈由 `BattleScene` 渲染为 y = 0.4 的地面圆环，开启深度测试、关闭深度写入，并应用战争迷雾。车身、脚部与前景建筑会遮住圆弧；2D 覆盖层不再重复绘制选中圈。不同单位复用圆环几何与阵营材质；屏幕导数控制约 1.5px 描边，选中才产生该网格的绘制。
- **[SELECTION-RESOURCES]** 建筑、资源和攻击范围均使用同一地面圆环，不能在 Canvas 覆盖层重画。建筑半径按实际占地对角线的一半加 6 世界像素计算；资源半径为资源占地半径加 12。资源悬停和选中使用资源色；点击选中时显示真实剩余量。资源耗尽、消失、切换地图及重置场景时清除其标记。2D 降级模式先画全部圆环，再画任何模型。
- **[HEALTH-ANCHOR]** 血条保留在屏幕信息层。静态模型及旋转天线按网格包围盒投影；移动单位为各骨骼缓存局部包围盒，再随当前姿态变换投影。共用几何只遍历一次顶点，不逐帧计算所有蒙皮顶点。血条在投影包围盒上方留出间距，缩放时限制宽度，避免压住头部或天线。
- **[HEALTH-VISIBILITY]** 开启生命值显示时，仅选中或受伤单位显示血条，包含建筑。3D 血条为 5px 圆角细条，60% 以下使用琥珀色、30% 以下使用珊瑚红；受伤单位优先占位，重叠时最多上移三行，仍拥挤的满血条省略。
- 初始阵容在三个镜头旋转角度 × 三个缩放倍率（0.65 / 1.5 / 2.4）下，逐顶点检查实际动画轮廓，血条下沿与模型最少间距为 6.04px；取消选择后地面光圈全部隐藏，WebGL 错误码为 0。
