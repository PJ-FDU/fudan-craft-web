# 七项游戏改进与验收

源码为唯一事实来源。此清单记录本轮实现范围与验证结果，参数以对应 TypeScript 模块为准。

## 实现范围

- [x] 联机断线重连：原席位令牌、限时恢复、自动重试；房间定期原子存档，服务重启可恢复。
- [x] 手机操作：触屏编队保存 / 召回、空闲工人入口、兵种筛选与排除工人、按屏幕像素计算点选容错。
- [x] 自适应性能：根据实际帧耗时调整分辨率 / 阴影 / 光照，提供自动 / 画质 / 省电模式，避免频繁切档。
- [x] 大部队交通：混编尺寸通行、对向让行、长时间卡住后的绕行；80 单位和运输交付压力场景。
- [x] 平衡数据：收入 / 支出 / 退款、伤害与兵种交换、工人闲置、经济时间序列；战后可查看并导出；提供可重复的对抗基准。
- [x] AI 战略：有时效的可见侦察记忆、扩张与进攻计划、快攻 / 经济 / 稳守 / 均衡风格，不读雾内实时敌方状态。
- [x] 朋友合作：人类同队对抗 AI、共享视野、盟友免伤与治疗、团队胜负、同房间再战。

## 工程约束

- 保留既有单机、v2 存档、2–4 人自由对战、双语及 2D 兼容路径。
- 玩家所有权和团队关系分开：盟友单位可见但不能越权指挥；经济和科技仍独立。
- AI 继续使用玩家相同的权威命令和经济规则。
- 手机三击全选保留包含工人的语义，提供显式筛选。
- 临时验证脚本 / 日志放在工作区外；可复用的基准脚本与正式回归保留在工程中。

## 使用与部署

- `[ROOM]` 联机创建页面选择「朋友合作对抗 AI」或自由对战。原席位保存在当前标签页 `sessionStorage`，刷新会自动重连；主动离开撤销令牌，其他标签页不能仅靠房间码占用已开局席位。不重放断线期间的指令。
- `[PERSISTENCE]` 默认快照目录为 `.rooms/`。容器重建时使用 `ROOM_STORE_DIR` 复用持久目录。正常关服先保存，异常退出可从最近一次成功写入的快照恢复。无在线玩家时暂停模拟，所有保留席位过期即移除空房。等待或已结束的房间无操作 30 分钟会过期，进行中的房间为 24 小时。 [公网部署](../README.md#公网部署)
- `[PERFORMANCE]` 设置 / 战局菜单均可选择自动、画质、省电。自动降低分辨率、阴影尺寸 / 更新频率、GI 上限；自动变化不会覆盖用户光照偏好。画质模式仍遵守手动光照选择和设备支持能力。
- `[REPORT]` 战局菜单和结束界面均可查看统计、导出 JSON。胜负确定前只含本人统计；确定后包含全部阵营，不泄露战中敌方经济。
- `[BENCHMARK]` `npm run benchmark`；可用 `npm run benchmark -- <输出目录> <模拟秒数>`（60–3600）。报告：[balance.md](benchmarks/balance.md)，原始数据：[balance.json](benchmarks/balance.json)。完整合作局由 AI 代行人类下单，432.3 秒结束；镜像结果和兵种存活数均保留，少量确定性样本不解释为玩家胜率。

上述浏览器验证使用桌面 Chrome 的触屏模拟与软件 3D 渲染。真机功耗和触控手感仍需单独测量。

## 移动端首屏

2026-11-20 在两版本的本地生产构建上做冷缓存对照。使用桌面 Chrome 的移动模拟，视口为 390 × 844 CSS 像素，设备像素比为 2，网络延迟为 150 ms，下行约 1.6 Mbps。测量到首页请求完成为止，无存档、无联机席位、无点击交互。传输量为导航与资源的 `encodedBodySize` 之和，按十进制 KB 四舍五入。FCP 为首次内容绘制，LCP 为最大内容绘制。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首页 HTML 与资源传输量 | 979 KB | 192 KB |
| 移动端封面 | 221 KB JPEG | 37 KB WebP |
| FCP | 2.32 秒 | 0.71 秒 |
| LCP | 2.80 秒 | 0.71 秒 |

这是该次模拟的首屏记录。进入首局的耗时、真实蜂窝网络和移动设备功耗需要分别测量。

复测时先执行 `npm run build` 和 `npm start`，用干净的浏览器会话打开首页。应用同一视口和网络配置，关闭缓存，先记录首次导航的 Network 和 Performance，再点击「新的战役」。首屏应只请求首页入口及其直接资源，选菜单时加载游戏模块，确认部署后加载战场图集和 3D 场景。另用有存档的会话刷新，确认「继续远征」可用。 [首页入口](../src/home.ts) · [首页控件](../src/shell.ts) · [封面规格](GENERATED_ART.md#远征主菜单场景)

## 公网联机工程记录

| 行为 | 实现 |
| --- | --- |
| 升级与连接回收 | 按 Origin 和连接上限检查 `/ws`。只有来自指定直接代理的 `X-Real-IP` 会参与限流。所有已建立的连接参与 30 秒心跳，未入房或已离房的连接按配置回收。 |
| 联机快照 | 服务端以 20 Hz 模拟，正常以 10 Hz 发送按席位过滤的状态。支持 `permessage-deflate` 的客户端可以接收压缩快照。同一连接有快照等待发送时，跳过中间快照，空闲后发送最新状态。 |
| 持久化与重连 | 房间事件触发的写入会合并，定时保存周期为 10 秒，正常关服保存最新快照。浏览器共用正在建立的 WebSocket，并用指数退避和随机抖动重连。 |
| 静态资源 | HTML 使用 `no-cache` 重新验证，带构建哈希的 JS 和 CSS 使用一年的不可变缓存，其余静态资源默认缓存一小时。资源支持 `HEAD` 和 ETag 条件请求。 |
