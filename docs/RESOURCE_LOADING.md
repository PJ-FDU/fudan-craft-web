# 资源加载与体积优化

实现以 `scripts/build-runtime-assets.mjs`、`src/game/resource-loading.ts` 和
`src/game/model-resources.ts` 为事实来源。以下体积基于当前美术源文件，修改美术后应重新运行检查。

## 当前结果

| 场景 | 模型、材质及必要共享图集 | 相对原全量 Blender 资源 |
| --- | ---: | ---: |
| 原全量模型和 PNG 材质 | 221.894 MiB | — |
| 首次模型图鉴：工业采集车，高清材质 | 13.695 MiB | 减少 93.8% |
| 默认战场：工业 + 生群，含环境 | 53.499 MiB | 减少 75.9% |
| 四种族战场，含环境 | 91.657 MiB | 减少 58.7% |

统计口径：`npm run check:runtime` 对所需文件去重求和；不含入口 JS、
字体、音频、档案肖像和运行时清单。页面进度包含本次登记的清单和复用资源，
因此其总量与本表可能略有差异。这些是文件体积，不是固定的等待时间。

## 加载行为

- 战场只预载参与种族的完整科技树、收拢形态及环境模型。联机以首个权威状态中的玩家种族为准，
  包含 AI；读档使用存档中的种族；地图编辑器加载全部种族。
- 模型图鉴独立加载当前对象的高清模型和材质；切换对象增量下载。
  请求版本号防止快速切换或关闭图鉴后，旧请求覆盖当前预览。
- 2D 动画图集只在打开动画图鉴时加载。战场小地图使用独立的 256 像素地表图。
- 同一资源的下载、图片解码及模型解析会复用。下载同时最多执行六项；
  30 秒没有收到数据时终止该请求，失败缓存被清除，允许用户重试。
  快速取消再进入时共用场景初始化，避免重复创建 GPU 场景。
- 加载界面展示流式读取的真实字节、文件数量和下载百分比；
  总大小未知时显示不确定进度，下载完成后仍需解码与初始化场景。
  百分比不代表 GPU 初始化完成，也不使用时间估算伪造进度。
- 返回主菜单会立即退出等待界面并注销进度监听。已启动的共享下载继续，
  后续进入可复用结果；该操作不终止浏览器中的全部网络请求。

## 派生资产

`public/assets/runtime/` 是忽略提交的生成目录。普通开发和两种构建入口
通过 `predev` / `prebuild` 自动生成，原始美术文件保持为生成输入。

- 按模型抽取独立 GLB，保留 Meshopt 压缩、顶点数据、骨骼和活动部件。
- 从 GLB 的实际 UV 求出材质图块，裁剪后通过纹理变换保持 UV 对应关系。
- 图鉴保留原图块分辨率；战场使用最大 1024 像素的派生材质。
  颜色图使用高质量 WebP，高清法线和 ORM 使用无损 WebP。
- 文件名携带内容指纹，服务器使用一年 `immutable` 缓存；
  清单使用 `no-cache`，源文件或生成规则变化会失效生成缓存。
- Pages 构建保留全部公共源素材以符合现有发布检查。
  发布包总大小与单次页面下载量是不同指标。

```sh
npm run assets:runtime
npm run check:runtime
npm test
npm run build
npm run build:pages
node scripts/check-pages-build.mjs
```

`check:runtime` 校验全部 95 个模型、242 个网格的顶点属性和索引与源文件一致，
逐像素校验高清法线 / ORM 裁剪，并检查紧凑纹理尺寸、科技树完整性、
内容指纹与清单文件大小。

浏览器已验证首模型按需请求、四种族切换、建筑与收拢形态、模型与战场下载失败重试、
战场实际进度、退出等待及再次进入、更换对局阵容。动画图鉴打开后才请求 16 份
动画 WebP，全部成功，未请求旧动画 PNG。开发服务器原有 HMR 端口冲突不影响资源请求；
生产构建仍有较大 JS 分块提示，后续可单独处理入口代码体积。
